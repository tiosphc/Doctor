# DrJunie - UI source inventory (Phase 1)

Audit date: 2026-10-29. Read every `createFileRoute` in `src/routes/*.tsx` and verified its `fullPath` in `routeTree.gen.ts`. URLs below come from the generated route tree, not filename guesses.

135 route definitions excluding `__root.tsx`: 107 page definitions and 28 layout definitions; 107 URL patterns after normalizing trailing slashes. A layout and its index can share a URL; they are not two screens. `$id`, `$slug`, etc. are dynamic parameters. `booking_.success.tsx` resolves to `/booking/success`.

Root: `routes/__root.tsx` -> QueryClientProvider -> AuthProvider -> SiteLayout -> Outlet. Toaster is outside SiteLayout. This inventory records existing source; it changes no routes or access rules.

## Scope notes

- `/cart`, `/checkout`, `/checkout/success/$orderId` belong to Phase 2 despite requiring authentication through RetailGuard. `/my-orders/*` belong to Phase 3 and use AccountShell.
- `/dealer/apply` belongs to Phase 5 and uses public SiteLayout instead of DealerLayout, but still inherits the customer role guard of `/dealer`. Do not make it anonymously accessible.
- `/doi-ngu-bac-si` renders its own Landing Nav/Footer. `/doctors` and `/doctors/$slug` use regular SiteLayout. Keep these routes distinct.
- `/setup-password` uses regular SiteLayout, unlike login/register/forgot-password, which use LovableFlowLayout.
- `/doctor/schedule` exists but is absent from doctorLinks in StaffLayout. Record it for UI coverage; do not add navigation or functionality during audit.
- Current routes do not import `pages/HomePage.tsx` or `pages/BookingPage.tsx`; active implementations are LovableHomePage and TwoStepBookingPage. Do not delete legacy files in Phase 1.
- Source contains 333 native `<button>` and 45 native `<table>` declarations, including legacy files. These counts measure presentation spread, not rendered elements or required replacements.
